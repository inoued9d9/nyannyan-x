# HTML制限表示ベースの自動判定 / v0.6.0 β

更新日: 2026-09-26。利用者がX APIを使わない方式を選択したため、HTMLで制限表示を確認し、候補の外側本文をJevへ自動送信する機能を実装しました。以前の個別確認方式より誤送信リスクが高い方式です。**鍵マークがないことを公開性の証明とはしません。** 初期OFFで、設定画面の初回ON時に検出漏れ・課金・取消不可への同意を求めます。

## 現行の表示動作

1. ホーム・投稿詳細・検索の候補を一時的に隠す。鍵・限定表示、DM・入力欄、曖昧な本文、非表示と検出した投稿は送信対象外。本文の子要素・祖先要素の非表示も検査し、検出時は部分送信せず投稿全体を未判定とする。拡張自身の覆いは区別する。検出条件と限界は [PRIVACY](../PRIVACY.md) を参照。
2. 拡張・Jev・自動設定ON、確認済みsessionキー、通信権限、送信枠を確認。画面内と直下約300pxを優先し最大2件を並列処理。背景タブは新規送信しない。
3. 引用RTは外側本文だけを送信。本文の内容と言い方から「読んで嫌な気持ちになる程度」を1つのプロンプトで評価する。正常な結果の `score / 3 × 100` が設定閾値未満なら表示、以上なら猫カードへ置換する。初期閾値25。個別クリック不要。
4. 短文・文脈不足・確信度の低さによる保留はしない。通信・応答検証の失敗等は判定と区別する。「判定エラーの投稿は原文を表示する」は初期OFF。ONではエラーの投稿やエラーで自動停止中の未判定原文が見えるため、不快な投稿が表示され得る。未設定や自動送信上限だけを理由とする判定待ちは一律に解除せず、判定中の仮覆い、高スコアの猫表示、引用RT一括非表示も維持する。
5. 原文ボタンは既存設定に従う。引用RT一括非表示がONなら、引用RTを判定キューへ入れず端末内だけで隠す。送信対象外の通常投稿は未判定で原文維持、DMは表示変更もしない。

既に描画されたページや拡張起動前のフレームまで不可視にする保証はできない。通常の新規読み込みとSPA追加は、対象画面限定の初期CSSとMutationObserverを組み合わせて漏れを検証する。DMと入力欄は仮覆いからも除外する。

## キュー・費用・エラー

- 通常の同時通信はworkerで全タブ合計2件に制限。200件/sessionの枠を送信前に直列予約し、最後の予約済み処理は完了可能。取消・失敗の枠は戻さず、キー交換・自動OFF→ONでも枠は戻らない。手動判定・接続確認・入力文の判定テストは別枠で、料金上限ではない。
- 各タブでIDと本文が同じ結果・試行済み状態を最大200件メモリ保持。取消／到達不明の処理を接続状態の回復だけで自動再送しない。閾値変更は数値を再利用。
- 通信エラーではそのタブの新規送信を一時停止。認証・利用上限・タイムアウト・ネットワーク・応答形式などの固定分類だけを表示し、生の例外やサーバー本文は表示しない。接続確認後、自動OFF→ONで明示的に再試行可能（再課金の可能性あり）。
- Jevへの自動再試行はしない。例外は拡張内部の混雑で**未送信と確認できた要求**の待ち直しだけ（1.5秒間隔・最大3回）。
- Jevへ送る質問は `questions.discomfort` のScore1つ。基準は0「嫌でない」・1「少し嫌」・2「はっきり嫌」・3「強く嫌」。確信度・攻撃確率・文脈十分性の追加ゲートはない。不快さは主観的で、精度・閾値は未較正。質問を減らしたことによる実APIの速度改善も未確認。

## キー確認と取消

設定では自作テスト文を入力し、OK・NGと1つの不快度スコアを確認できます。通信失敗は判定エラーとして別表示します。最後の投稿応答エラーの固定診断コードは[応答の診断](response-diagnostics.md)を参照してください。テスト文の明示送信は自動200件枠とは別です。

「保存して接続確認」はJev OFFでも固定の架空日本語文を1回送ります。未入力／未確認／確認中／確認済／失敗を表示し、自動判定には確認済のキーを要求します。キーはsession限定で投稿側スクリプトへ返しません。確認済表示は確認時点の結果で、継続的な接続保証ではありません。

本文・ID・制限表示・画面・設定変更時は処理を中止し古い結果を適用しません。中止や削除でも送信済みデータは回収できません。[PRIVACY](../PRIVACY.md)と[リスク](../LIMITATIONS.md)を参照してください。

## 検証と方式の選択

架空DOM・架空キー・模擬API応答で単体・ブラウザ・実MV3を検証します。実Xの全HTML、実Jevの遅延・精度・料金は別検証。利用者の画面で観測された保留の原因を、模擬テストだけで確定したとは扱いません。[確認表](acceptance.md)

X App-only API経由や端末内モデルも以前検討しましたが、今回の利用者の選択により実装していません。HTML方式の採用は、公開性の保証、Xの用途許諾、第三者送信の包括的許可を意味しません。
