# 応答エラーの診断 / v0.6.0 β

## 接続確認済みなのに停止する場合

「接続確認済み」は固定文1件を正常に評価できた時点の結果です。実投稿の成功を保証しません。「応答の検証で停止」は、単なる未応答・タイムアウトとは別です。

設定の「最後の投稿判定エラー」に固定コードと時刻を表示します。本文・投稿ID・アカウント・キー・生のJSONは記録しません。全タブ共通で最後の投稿エラー1件をsession保持し、接続テスト成功では消しません。キー保存・削除、sessionの消去でリセットします。履歴が残っていても、現在すべてのタブが停止中という意味ではありません。

| コード | 拒否した条件 |
| --- | --- |
| HTTP_SHAPE / JSON_DECODE | HTTP応答形式 / JSONの読み取り |
| ENVELOPE / MODEL / ANSWERS | 応答全体 / 固定モデル名 / 回答一覧 |
| QUESTION | 不快度の判定項目の欠落・型 |
| SCORE / CONFIDENCE | スコア / 確信度の型・範囲 |
| PROBABILITY_KEYS / PROBABILITY_VALUE | 確率分布の項目 / 各値 |
| PROBABILITY_TOTAL / SCORE_MEAN | 確率の合計 / スコアと分布の整合性 |
| CACHE | 評価済みデータの再適用 |

不具合を報告するときは、版番号とコードだけを共有してください。APIキー、実投稿、NetworkのHAR、生のAPI応答を公開しないでください。修正後は拡張とXのタブを再読み込みし、必要ならキーを再入力します。X再読み込みや自動OFF→ONでは再送信・課金の可能性があります。

## 数値の互換方針

[TypeSafe API仕様](https://docs.typesafe.ai/api)では、Scoreは各レベルの確率と加重平均scoreを返します。[公式Scoreの例](https://docs.typesafe.ai/primitives/score)には小数2桁の値がありますが、丸め桁数の保証は確認できません。

旧実装は確率合計との差を1e-6、scoreと確率から再計算した期待値との差を0.005001までしか許容しませんでした。例えば元の分布 `[.104,.104,.196,.596]` を独立に丸めた `[.10,.10,.20,.60]` とscore `2.28` は、期待値 `2.30` との差で拒否されます。これは**合成データによる再現**であり、利用者の実API応答を取得した結果ではありません。

v0.5.1は各値最大±0.005の独立丸めを想定した互換上限を設けます。4確率の合計差は `4 × .005 + 1e-6`、期待値との差は `(0+1+2+3) × .005 + .005 + 1e-6` までです。APIの保証ではなく拡張側の方針です。超過、欠落、文字列値、NaN、範囲外値、異なるモデルなどは引き続き拒否します。

この数値検証の互換幅はv0.6.0でも維持します。確率の再正規化やscoreの置換は行いません。表示桁の丸めで閾値を超えたものとして扱う変更もありません。エラー時の自動連続再送はしません。

v0.6.0では判定仕様自体を変更し、`questions.discomfort` のScore1項目だけにしました。API応答のconfidenceは型・範囲を検証しますが、猫表示の条件や保留条件には使わず、画面にも表示しません。正常な不快度スコアを0〜100に換算し、設定閾値以上なら猫、未満なら原文を表示します。旧4項目の結果を新判定に転用せず、異なる評価基準のキャッシュは拒否します。

## テスト文と判定精度

設定の入力文テストは実際と同じモデル・1つのプロンプト・数値判定を使用します。本文以外のDOM送信条件や引用一括非表示は対象外です。自作の穏やかな文、具体的批判、嫌味、威圧的表現などを比較し、モデルの傾向を確認してください。v0.6.0では評価を「読んで嫌な気持ちになる程度」へ変更しましたが、日本語精度や応答時間が改善したとの実測はありません。不快さは個人差があり、法的な誹謗中傷を確定するものではありません。

テスト文と結果は設定ページのメモリだけで、外部送信は送信ボタンを押したときだけです。Jev OFFでも利用可能で、自動200件枠とは別に料金が発生し得ます。鍵投稿・DM・私的情報・APIキーを入力しないでください。ページを閉じても到達済みの送信は取り消せません。
