# 開発記録

## 2026-09-23 / v0.6.0 β

- 利用者の要望に合わせ、4カテゴリ＋文脈質問を廃止。「読んで嫌な気持ちになる程度」を本文の内容・言い方から評価するScore1質問へ変更。
- 正常な応答では0〜100換算スコアと設定閾値だけで猫表示を決定。確信度・文脈不足・攻撃確率による追加ゲートや保留を廃止。通信・応答検証エラー等の未判定表示は維持。
- 入力文テストも1つの不快度スコアとOK・NGへ変更。旧評価結果のキャッシュを拒否し、閾値変更時の追加送信はしない。
- 送信対象の制約・同意・引用分離・DM除外・費用制限は変更しない。実APIの日本語精度・応答速度の改善は未確認。[確認表](acceptance.md)参照。

## 2026-09-23 / v0.5.1 β

- 応答の独立丸めへの互換幅、固定診断コード、sessionの最後の投稿エラーを追加。実利用の原因確定ではなく合成再現に基づく対処。
- 設定画面に自作文章の判定テスト、OK・NG・保留と数値内訳、現行プロンプト閲覧を追加。本文の永続保存・暗黙の追加送信はしない。

## 2026-09-23 / v0.5.0 β

- 利用者がX APIなし・HTML制限表示の検出方式を明示選択したため、初回同意つき一括自動判定を実装。公開性の保証ではなく、制限検出漏れによる誤送信リスクを設定と文書に記載した。
- キー保存時の固定文接続確認、session検証状態、状態バッジを追加。Jev OFFでも明示的な確認通信を行う。
- 自動は2件並列・画面付近優先、非表示DOM除外、200件/session予約、200件メモリキャッシュ。取消後の無操作再送と最後の予約枠の中止競合を修正。
- 利用者の保留・遅延報告を受け、文脈／確信度／通信エラーの表示を分離。保留の原文表示を選択可能にし、エラーは新規送信を一時停止。判定基準や固定閾値の安全条件は変更していない。
- 架空データで検証。実API遅延・実X検出率は測定しておらず、報告された接続エラーの実原因を断定しない。[確認表](acceptance.md)参照。GitHub公開・pushなし。

## 2026-09-22 / v0.4.0 β

- 表示名を「にゃーんフィルター β」に変更。引用RTの外側本文だけを分離し、境界不明・本文なしを送信候補から除外。引用先の作者・制限表示を外側の投稿と混同しない。
- 設定に「引用RTをすべて隠す」を追加。攻撃性を判定しない端末内の一括表示変更で、鍵・不明な引用も「未判定」と表示。Jev送信は禁止し、ONへの切替で保留中の引用処理も中止する。DMは対象外。
- 投稿ごとの操作を不要にする自動Jev判定は未実装。以前の「公開確認した投稿だけ送る」条件を保ち、公開性の確認方法の選択を待つ。[設計と制限](automatic-filtering.md)を文書化した。
- 指定によりMITを採用。README、PRIVACY、LIMITATIONSに、送信本文・認証ヘッダー・通信メタデータと送らない情報、保存先、無保証・責任制限とその限界を記載。拡張にも説明ページとMIT本文を同梱した。
- 公開前チェック、第三者依存の説明、変更履歴、PRテンプレートを整備。CIへ文書整合性・秘密情報補助検査を追加。リモート作成・push・公開・ストア申請は未実施。
- Node単体47件、Chrome DOM31件、Edge引用18件、Edge実MV3 11件に成功。実投稿・有効なキーを使わず、外部通信は遮断した。静的・文書検査と参照可能履歴の補助監査も通過。実API・実X・GitHub Actionsは未検証。[確認表](acceptance.md)を参照。

## 2026-09-21 / v0.3.0

- Jev 1.13.0の固定APIクライアントとservice workerを追加。手動公開確認の1件のみ送信。APIキーはsessionのTRUSTED_CONTEXTS限定、設定画面から登録・削除。
- 日本語4カテゴリ＋文脈十分性、厳格な応答検証、失敗時未判定、取消・並行上限・タイムアウトを追加。実APIへの接続試験はキー未入力のため未実施。
- Chromeの拡張アイコンに「APIキー・フィルター強度を設定」を追加。強度・原文ボタン・開発表示をブラウザから変更可能。
- 検索を対象に追加。通常のXではテスト操作を非表示。原文ボタンは既定OFF。
- Xのarticleがflex rowの場合に診断欄が右列へ伸びる問題を、拡張UI付与中のcolumn配置で修正。元のinline styleは変更せず、停止時に拡張属性を除去して復元。
- 猫カードを小型化し、顔文字と吹き出しを追加。閾値はローカル数値の再判定で反映し、再送信なし。
- GitHub準備としてCI、Issueテンプレート、SECURITY、CONTRIBUTING、PRIVACY、公開前チェックを追加。リモート作成・push・ライセンス選択・公開は未実施。
- Node 46件、Chrome/Edge DOM 31件ずつ、実MV3 Edge 9件に成功。詳細は [確認表](acceptance.md)。実データ／有効なキーは使用していない。

以下は初期版の記録であり、当時の「未実装」の記述は現行機能を表しません。

## 2026-09-20 / Phase 1

独立したローカルGitリポジトリ、mainブランチを作成。リモートリポジトリは設定しない。拡張本体にビルドや依存ライブラリは不要。

当初の「送信不可を猫化」から、ユーザーの訂正に従い以下に変更した。

- 対象外は判定せず原文維持、未判定理由を表示。
- 公開制限を検出しなかった構造上の候補と、実送信の許可を分離。`canSend`は全件false。
- API接続前の表示検証に限り、候補を明示的に高攻撃性と仮定できる。
- 置換時は名前「ねこ」、鳴き声6種。実採点の表示と誤解されないラベルを付ける。
- 自分のXアカウントでの非公開テスト用。公開・配布・Jev通信はしない。

## 未検証

本人のアカウント上のX DOM、各種言語や段階配信によるレイアウト差、鍵や購読者限定の検出率。これらは手動の受け入れ確認で検証する。診断の候補表示だけでAPI送信を有効化しない。
