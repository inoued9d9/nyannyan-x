# GitHub公開の準備

この文書は、所有者が公開内容を確認できるようにするための手順です。文書やCIの追加によってGitHubへの公開、リモート作成、push、ストアへの配布が行われることはありません。**公開の許可・準備完了を示すものではありません。**

現在の機能は [README](../README.md)、送信・保存する情報は [PRIVACY.md](../PRIVACY.md)、免責と既知の制限は [LIMITATIONS.md](../LIMITATIONS.md)、利用許諾は [LICENSE](../LICENSE) を参照してください。Xに関する調査結果は [規約調査メモ](x-terms-review.md) に記載しています。公開候補のコミットを決めた時点で、これらの文書と実装が一致しているか再確認します。

本プロジェクトにはMIT Licenseを採用します。プロジェクト貢献者の著作権表記と許諾文を含む `LICENSE` が条件の本文です。プロジェクトのコードに対する再利用権は、Xの投稿データ・API・商標・ロゴ、Jevその他の第三者サービスや素材の利用許諾には及びません。この文書の公開手順やデータ取扱方針は、MIT Licenseへ追加する禁止条件ではありません。

## 公開するフォルダー・公開しないフォルダー

- `docs/` は公開対象です。仕様、検証範囲、既知の制限、規約の調査記録を含み、READMEからも参照します。実投稿・秘密情報を追加しないでください。
- `artifacts/` は公開しません。テストで生成した画像や一時ブラウザプロファイル等の保存先で、`.gitignore` の除外対象です。拡張の実行には不要です。
- 拡張を読み込むフォルダーは `extension/`。ソース公開時はREADME、MITの `LICENSE`、プライバシー・免責説明、テストやCIも含めます。

`.gitignore` は、すでに追跡済みのファイルやブラウザからの手動アップロードを除外しません。公開前に `git ls-files artifacts` が空であることを確認し、フォルダー丸ごとのZIPやドラッグ＆ドロップでは `artifacts/`・認証情報・ブラウザデータを含めないでください。

## 公開前に所有者が確認すること

- [ ] **現行規約と用途の許諾**: 公開時点で施行されているXのTerms、Developer Agreement / Policy、Jevの利用・データ取扱条件を確認し、この取得・表示変更・外部推論送信・配布という用途に必要な許諾を確かめる。これらの適用と許可は未確定。個人利用、DOM方式、公開投稿、利用者の同意だけから包括的な許可を推定しない。
- [x] **ライセンス採用**: 所有者の指定によりMIT Licenseを採用。著作権表記はプロジェクト貢献者とし、許諾・無保証・責任制限の本文を [LICENSE](../LICENSE) に置く。
- [ ] **依存物の確認**: 配布するコード・画像・ライブラリの出所とライセンス、必要な表示を確認する。第三者のX投稿や画像を同梱しない。
- [ ] **秘密情報と履歴の監査**: 作業ツリー、追跡ファイル、公開対象ブランチ・タグの全履歴を確認する。下記の補助検査はヒューリスティックであり、秘密や実投稿が含まれないことの証明ではない。`.gitignore`、静的チェック、補助検査の成功だけで監査完了としない。
- [ ] **自動Jev判定の説明**: 現行版は利用者選択によるHTML制限検出方式。初回同意、確認済みキー、200件/session上限を備えるが、公開性を証明せず非公開本文を誤送信するリスクがあると明記する。判定は「読んで嫌な気持ちになる程度」1項目と閾値だけで、主観的な評価であると説明する。未判定の原文表示の選択肢・原文フラッシュ・実精度と遅延未検証も説明し、引用RT一括非表示とは区別する。
- [ ] **検証と説明**: 公開候補のコミットでunit testと静的チェックを実行する。架空データのブラウザ検証と実環境の検証を分けて記録する。実APIの接続・課金・応答、および実XのDOM検出率・日本語判定精度は未確認であることを明記する。送信本文に識別情報が含まれ得る点や誤判定など、[PRIVACY.md](../PRIVACY.md) と [LIMITATIONS.md](../LIMITATIONS.md) の説明も確認する。
- [ ] **公開窓口**: 所有者・保守方針・不具合報告方法を確認する。GitHub側でPrivate vulnerability reportingを有効にし、非公開報告を受け取れる状態を確認する。
- [ ] **公開範囲**: リポジトリの公開、拡張の配布、ストア申請、紹介動画の公開をそれぞれ確認する。今回の準備にこれらの実行は含まれない。

## ファイルとGit履歴の確認

次のコマンドは読み取り用です。出力はまず手元で確認し、実データを含む結果を公開Issueなどへ貼り付けないでください。

```text
git status --short
git diff --stat
git diff --cached --stat
git ls-files
git log --all --oneline --stat
git remote -v
```

APIキー、`.env`、認証ヘッダー、Cookie、ブラウザプロファイル、実投稿、実TLのスクリーンショットや動画、HTML/HAR/通信ログ、`artifacts/`、バックアップや配布ZIPを確認対象にします。秘密情報スキャナーも全履歴に対して実行し、その結果を人が確認してください。上のコマンドや `scripts/check.mjs` だけでは秘密情報を網羅的に検出できません。

補助として `node scripts/audit-public.mjs` は公開候補のファイルと全参照可能コミットに対し、生成物・秘密ファイル名と一般的な認証情報形式を読み取り専用で検査します。疑わしい値は出力せず、ファイル名だけを報告します。これは既知の特徴に基づくヒューリスティック検査で、実投稿・画像・未知形式のキー、参照されなくなったGitオブジェクト、別の場所に保存されたログ等を網羅するものではありません。目視確認を省略しないでください。

漏れた認証情報は削除だけで済ませず、提供元で失効・再発行します。過去のコミットに含まれていた場合は公開を止め、所有者が履歴の扱いを決めてから再監査します。履歴の書き換えやリポジトリの削除を、この文書の確認だけで自動実行しないでください。

## CIが確認する範囲

[CI設定](../.github/workflows/ci.yml)はNode.js 24で次を実行します。

```text
node --test tests/*.test.mjs
node scripts/check.mjs
node scripts/check-docs.mjs
node scripts/audit-public.mjs
```

`main` へのpushと、`main` を対象とするPRがトリガーです。権限は `contents: read`、checkoutの認証情報保存とnpmキャッシュはOFFで、実APIキーを渡しません。履歴を取得し、参照可能コミットも補助検査します。単体・静的・文書・補助監査は依存パッケージのインストール不要です。GitHub Actions自体はリポジトリ未公開のため未実行です。

ブラウザテストは任意のローカル検証で、現時点のCIには含みません。`node scripts/quote-tests.cjs` では、自作の架空投稿を使って引用本文の分離、一括非表示・復元、DM除外などを確認できます。その他の手順は [CONTRIBUTING.md](../CONTRIBUTING.md) を参照してください。CIが通っても実際のXのDOM、Jevの実通信、モデル精度、規約適合性や秘密履歴監査の完了を保証しません。

Actionのバージョンは2026年9月21日に公式の [checkout v7.0.0](https://github.com/actions/checkout/releases/tag/v7.0.0) と [setup-node v7.0.0](https://github.com/actions/setup-node/releases/tag/v7.0.0) のリリースを確認して指定しています。更新時は公式リリースと変更点を確認してください。

## 公開後の窓口と説明資料

Private vulnerability reportingは [SECURITY.md](../SECURITY.md) の所有者向け手順で設定します。このファイルの存在だけでは有効化されません。設定と通知を確認するまで、非公開報告を受け付けられると告知しないでください。

Issue、README用画像、紹介動画、Releaseの添付物には自作の架空データだけを使用します。実際のタイムラインを猫化した画面にも識別可能な情報が残り得るため、公開用素材に使いません。架空デモでは「架空投稿」「ブラウザ内の表示変更」「手動テストかAPI判定か」を実際の動作に合わせて説明してください。
